# Совместная работа двоих над Terraria-Rust: ветка = заявка

**Summary:** каталог задач общий (`docs/ROADMAP.md`); заявка на задачу = ветка с её ID,
запушенная в `origin` сразу после создания; мерж в `main` — только после верификации.

**Date:** 2026-11-01 · **Status:** draft — оба решения выбраны пользователем явно
(AskUserQuestion), grill/cold-read пропущены: соглашение из двух пунктов.

## Решения

1. **Ветка = заявка (динамическое распределение).** Жёсткий сплит по милстоунам или
   крейтам не вводим: берём любую свободную строку каталога. Ветка с ID строки
   (например `M1.4-BG-11-cloud-parallax`) означает «строку взяли». Перед взятием —
   `git fetch && git branch -a`. Это родной механизм AGENTS.md, друг его и закладывал.
2. **Пушим ветки сразу.** Старое правило «не пушить без явной просьбы» заменено:
   ветку задачи пушим в `origin` сразу после создания, чтобы второй соавтор видел
   заявку. Мерж в `main` — только после верификации (тесты + скриншоты); push `main`
   — по договорённости, force-push запрещён. Правило внесено в `AGENTS.md`
   («Practical limits»).

```text
Ты работаешь в репозитории Terraria-Rust — faithful (1:1) реимплементация
Terraria 1.4.5.8 на Rust: то же поведение, те же константы, те же пиксели, другой
движок. Платформа Windows, shell — Git Bash; репозиторий уже склонирован в
E:\Terrustaria, рабочая директория выставлена автоматически, cd не нужен.

ПЕРВОЕ ДЕЛО — прочитай три файла (в этом порядке, полностью):
1. AGENTS.md — правила работы: branch-per-task workflow, карта архитектуры, золотое
   правило порта, инварианты детерминизма, верификация.
2. docs/ROADMAP.md — секция "Task catalog" в начале файла: каталог задач по
   милстоунам, каждая строка = готовое имя ветки. Это ЕДИНСТВЕННЫЙ источник задач.
3. docs/ARCHITECTURE.md — карта дерева модулей (куда расширять код).

РАБОЧИЙ ЦИКЛ (branch-per-task, строго):
1. git checkout main && git pull && git fetch --prune  — свежая main.
2. git branch -a — задачу никто не взял? (ветка с её ID = взято; ветки пушим сразу,
   заявка видна соавтору в origin).
3. git checkout -b <Task-ID>-slug && git push -u origin <Task-ID>-slug — ветка ровно
   под одну задачу из каталога. Не стекуй чужие задачи.
4. Работай: частые императивные коммиты. Каждая константа/логика — только из
   декомпила в decompiled/ (читай функцию целиком + вызывающих). Имена — читаемые
   Rust-имена, НЕ копии C#-идентификаторов, но каждая портированная строка несёт
   цитату // File.cs:NNNN — не удалять и не терять при переносе.
5. Перед мержем: git merge main внутри ветки; конфликты решай ОБДУМАННО
   (--ours/--theirs/-X запрещены). Затем верификация на слитном состоянии.
6. git checkout main && git merge <ветка> && git branch -d <ветка>; push main — по
   договорённости с соавтором.

ЖЁСТКИЕ ПРАВИЛА:
- Тесты: cargo test --workspace -- --skip migrates_version_2_kinds_to_item_ids —
  cargo может вернуть код 1 ПРИ УСПЕХЕ; судить ТОЛЬКО по строкам "test result: ok"
  и "0 failed".
- Детерминизм — инвариант: RNG-потоки (FastRandom, worldgen xorshift), содержимое
  G6 WorldFrameKey и порядок фиксированных шагов не менять; касаешься — побайтовое
  доказательство.
- НЕ запускай cargo fmt/rustfmt на crates/tr-core/src/tiledata/ и на
  crates/tr-core/src/wld.rs; правки таблиц — через tools/GenTileData (регенерация
  обязана давать пустой diff).
- НЕ редактируй README.md и docs/superpowers/ (локальные архивы сессий).
- НЕ делай git stash, НЕ аменди чужие коммиты, НЕ форс-пуши.
- Поиск по коду: сначала graphify (graphify query "..." --graph
  graphify-out/merged-graph.json), grep — только для подтверждения.
- Всё, что намеренно отклоняется от C#, — в docs/ANALYSIS.md с цитатой.
- Docs при завершении задачи: UI.md / ANALYSIS.md / PORT_MAP.md / ROADMAP.md
  (галочка у задачи). README.md — только для видимых игроку фич.

ЕСЛИ ДЕРЖАВКА ВАЖНЕЕ СКОРОСТИ: сомневаешься в поведении — перечитай C# в decompiled/;
непортированные вызовы — документированное отклонение, как принято в проекте.

ОТЧЁТ ПО ЗАДАЧЕ: имя ветки, коммиты, строки "test result:", скриншоты (если визуал),
отклонения. Задачу можно прервать — тогда остановись и отчитайся о состоянии ветки.
```
