# Landed-feature anchors — the tripwire against lossy merges.
#
# This repo is worked on by several agents at once, and some merges are
# wholesale (`git commit-tree` over a tree built from one side), so a merge can
# silently DELETE another agent's landed work with no conflict and no deletion
# commit of its own. That has already eaten BUG-21 twice, the whole
# `worldgen/dungeon_features.rs` (spikes + lights + wall variants) twice, and
# `touch_damage.rs`.
# Format:  <path relative to the repo root>|<marker>|<feature name>
# The marker must be a string that only exists while the feature does.
# Checked twice:
#   * `crates/tr-core/build.rs` — at build time, so a merge that drops work
#     stops compiling instead of shipping, and
#   * `crates/tr-app/tests/main_anchors.rs` — at test time, with the same
#     message.
# Add a row whenever you land a feature (one per major module/entry point).
# When a refactor legitimately renames something, update the marker in the same
# commit. Never delete a row to make a build pass — that is exactly the failure
# this file exists to catch.
